# 스터디 허브 Nuclino 참고 그린 리디자인 수정안

작성일: 2026-08-06
대상 저장소: `naemnaem99/study-system`

## 1. 목표

기존의 로그인, 개인별 스터디 노트, 23:50 자동 정리본, 수동 재생성, 마크다운 다운로드 기능을 보존한다. 그 위에 Nuclino의 장점인 계층형 탐색, 여러 보기, 그래프와 상세 문서의 분할 화면을 현재 스터디 시나리오에 맞게 도입한다.

완성된 제품을 한 문장으로 정의하면 다음과 같다.

> 네 명의 학습 기록을 작성자·날짜·주제 세 관점으로 탐색하고, AI가 하루 한 번 지식 지도로 정돈하는 팀 스터디 허브.

Nuclino의 로고, 문구, 고유 그래픽을 복제하지 않는다. 정보 구조와 상호작용 원칙만 참고하고, 브랜드·색상·콘텐츠·컴포넌트는 독자적으로 설계한다.

## 2. 사용자 시나리오

### 2.1 개인 기록 탐색

1. 사용자가 로그인한다.
2. 왼쪽 사이드바에서 `저장소`를 펼친다.
3. 하영·해냄·소정·유진 중 한 명을 선택한다.
4. 해당 구성원의 스터디 기록을 날짜·검색 조건으로 탐색한다.
5. 원본 노트를 열어 읽거나, 본인 노트라면 수정·삭제한다.

### 2.2 일일 정리본

1. 매일 23:50 KST에 그날 노트를 기준으로 정리본을 자동 생성한다.
2. 정리본에는 전체 한 줄 요약, 구성원별 요약, 실제로 존재하는 연결만 표시한다.
3. 구성원은 정리본에 댓글을 남긴다.
4. 노트가 변경된 경우에만 `변경된 노트 반영`으로 다시 생성한다.
5. 재생성 전 정리본은 버전으로 보존한다.

### 2.3 스터디 마인드맵

1. 사용자가 `스터디 마인드맵`으로 이동한다.
2. 왼쪽 그래프에서 전체 지식, 상위 주제, 세부 주제, 원본 노트 관계를 본다.
3. 노드를 선택하면 오른쪽 상세 패널에 AI 요약, 참여 구성원, 관련 주제, 근거 노트가 표시된다.
4. `그래프 / 목록 / 최근` 보기를 전환한다.
5. 작성자·기간·주제로 필터링한다.

├─ 홈
├─ 저장소
│  ├─ 전체 저장소
│  ├─ 하영
│  ├─ 해냄
│  ├─ 소정
│  └─ 유진

개인 저장소를 별도 데이터 저장소로 분리하지 않는다. 모든 노트는 `notes`에 유지하고 화면에서 작성자 기준으로 필터링한다.

|---|---|---|
| 저장소 | 작성자 | 기존 기능 재배치 |

| 마인드맵 | AI 주제 | 신규 기능 |

```text
┌──────────────────────────────────────────────────────────────┐
│ 그래프  목록  최근       [전체 구성원] [전체 기간] [검색]   │
├──────────────────────────────┬───────────────────────────────┤
│                              │ RAG                           │
│         ○ 알고리즘           │ 노트 8개 · 참여자 3명         │
│                              │                               │
│   ○ Frontend──● 지식맵──○ AI │ 핵심 개념                     │
│                    ╲         │ AI가 만든 누적 요약            │
│                     ○ DB     │                               │
│                              │ 구성원별 학습                  │
│  + / -   화면 맞춤           │ 관련 주제 · 근거 노트          │
└──────────────────────────────┴───────────────────────────────┘
              42%                            58%
```

- 그래프 배경은 흰색이 아니라 아주 옅은 녹색 종이 톤을 쓴다.
- 중심 노드는 가장 크고 채워진 녹색으로 표시한다.
- 상위 주제는 테두리가 있는 중간 크기 노드, 원본 노트는 작은 점으로 표시한다.
- 선택 시 연결된 노드와 선만 진하게 하고 나머지는 25% 불투명도로 낮춘다.
- 그래프 위치는 브라우저 레이아웃 엔진이 계산한다. AI는 위치를 만들지 않는다.
- 모바일에서는 그래프와 상세를 동시에 좁게 배치하지 않는다. 노드 선택 시 전체 화면 상세로 이동하고 뒤로 가기로 그래프로 돌아온다.

## 5. 디자인 방향

### 5.1 디자인 주제

확정 표시명: `Study Grove` — 개인의 학습 기록이 연결되어 팀의 지식 숲으로 자라는 공간.
태그라인: `Grow what your team learns.`

Nuclino의 빠르고 조용한 작업 화면을 참고하되, 빨간색 대신 `차분한 학습 녹색`을 사용한다. 산성 네온이나 금융 서비스 같은 진한 청록색을 피하고, 오래 읽어도 피로하지 않은 종이·잎·잉크 계열로 구성한다.

### 5.2 색상 토큰

| 이름 | 값 | 용도 |
|---|---|---|
| Study Green | `#2F7D5A` | 주요 액션, 선택, 중심 노드 |
| Leaf | `#74B892` | 보조 노드, 진행 상태 |
| Deep Ink | `#19352A` | 제목과 본문 |
| Grove Mist | `#EFF6F2` | 선택 배경, 그래프 배경 |
| Paper | `#FBFCFB` | 앱 배경 |
| Hairline | `#D8E5DD` | 경계선 |

오류는 의미 전달을 위해 별도의 빨간색을 유지하되 브랜드 색상으로 사용하지 않는다.

### 5.3 타이포그래피

- 큰 제목·문서 제목: `Noto Serif KR`, 500/600/700
- 본문·UI: `Noto Sans KR`, 400/500/600/700
- 날짜·필터·메타데이터: `Geist Mono`, 400/500
- UI 본문 기본 크기: 16px, 줄높이 1.65, 자간 -0.014em
- 문서 본문: 약 16.3px, 줄높이 1.88
- 큰 페이지 제목: 36~48px/1.18~1.3
- 사이드바: 13px/1.4

한국어 가독성은 산세리프 본문으로 확보하고, 학습 기록의 편집 문서 성격은 세리프 제목으로 드러낸다. 세리프는 제목에만 제한해 화면 전체가 장식적으로 보이지 않게 한다.

### 5.4 형태와 움직임

- 기본 정보 구조는 1px 경계선으로 나누고, 그림자는 주요 액션과 호버 상태에만 사용한다.
- 버튼 반경 12px, 정보 패널 반경 20~28px을 사용한다.
- 행 호버는 배경·포인트 선·텍스트 4px 이동을 200~220ms 안에 함께 처리한다.
- 페이지 진입은 520ms 한 번, Storyset 일러스트는 느린 부유 애니메이션 한 가지만 사용한다.
- `prefers-reduced-motion`에서는 그래프 전환 애니메이션을 제거한다.
- 모든 클릭 요소에 명확한 키보드 포커스를 제공한다.

### 5.5 대표 요소

제품을 기억하게 할 단 하나의 요소는 `자라나는 동심원 배지`다. 홈 참여자, 개인 저장소 프로필, 작성자 정보와 향후 마인드맵 중심 노드에 같은 성장 링을 사용한다. Storyset 그림은 팀 학습의 맥락을 보조하며, 인터페이스 구조를 대신하지 않는다.

### 5.6 Storyset 사용 원칙

- `Team work — Bro` SVG를 홈, 로그인, 개인 저장소의 팀 학습 안내에 제한적으로 사용한다.
- 원본의 초록 계열을 유지하고 자동 부유 애니메이션은 5.8초 주기로 적용한다.
- 무료 라이선스 조건에 따라 그림 가까이에 `People illustrations by Storyset` 링크를 표시한다.
- Premium 라이선스가 확인되기 전에는 출처 표시를 제거하지 않는다.
- 모든 그림은 정보 전달을 보조하며, 버튼·상태·데이터를 그림만으로 표현하지 않는다.

## 6. AI 무료 운영 설계

마인드맵을 열거나 노드를 클릭할 때 AI를 호출하지 않는다. 23:50 정리본 생성 요청 한 번에 아래 데이터를 함께 생성해 DB에 저장한다.

```json
{
  "one_liner": "string",
  "members": [],
  "connections": [],
  "note_topics": [],
  "topic_relations": [],
  "topic_updates": []
}
```

운영 규칙:

1. 입력 노트 해시가 같으면 수동 재생성 API를 호출하지 않는다.
2. 노트가 바뀐 경우 버튼 이름은 `변경된 노트 반영`으로 표시한다.
3. 동일 날짜의 동시 요청을 잠근다.
4. 실패 시 마지막 성공 정리본과 그래프를 유지한다.
5. API 한도 초과 시 새 노트를 `미분류`에 두고 다음 자동 실행에서 재시도한다.
6. 기존 주제 id를 우선 선택하고, 새 주제는 검토 상태로 제안만 한다.

## 8. 구현 단계

### 단계 1 — 앱 셸과 저장소 통합

- 그린 디자인 토큰
- 데스크톱 사이드바와 모바일 메뉴
- 저장소 하위 구성원 메뉴
- 홈·목록·노트·정리본의 공통 스타일 정리
- 기존 기능 회귀 테스트
- 개인별 그린 테마와 성장 링
- Storyset 팀 일러스트 및 출처 표기
- 행 호버·페이지 진입·reduced motion

### 단계 2 — 정리본 안전성과 댓글

- 입력 해시와 재생성 차단
- 정리본 revision 보존
- 댓글 CRUD와 RLS
- 정리본 우측 댓글 패널

### 단계 3 — AI 주제 분류

- 기존 Gemini 응답 스키마 확장
- `topics`, `note_topics`, `topic_relations` 마이그레이션
- 기존 주제 우선 매칭과 미분류 fallback
- 한 번의 23:50 호출로 정리본과 주제 분류 동시 저장

### 단계 4 — 마인드맵

- 그래프/목록/최근 탭
- 작성자·기간·주제 필터
- 그래프 노드와 관계선
- 우측 상세 패널
- 모바일 상세 전환

### 단계 5 — 검증과 배포

- 단위·RLS·빌드 테스트
- 키보드·스크린리더·reduced motion 검증
