## 1. 한 줄

4인 스터디 팀이 각자 공부한 내용을 올리고, 서로 읽고, 그날 올라온 것을 AI가 하나의 정리본으로 묶어주는 비공개 웹 서비스.

## 2. 왜 만드는가

스터디가 깨지는 이유는 대개 기능 부족이 아니다. **아무도 안 올리기 시작하면 끝난다.**

그래서 이 서비스의 설계 판단은 전부 한 방향을 향한다 — 올리는 마찰을 줄이고, 안 올린 상태가 눈에 보이게 만든다.

| 결정 | 근거 |
|---|---|
| 업로드 입력칸이 제목·날짜·본문 3개뿐 | 태그·카테고리 칸이 늘수록 업로드율이 떨어진다 |
| 홈에 팀 전체 업로드 현황(잔디 그래프)을 항상 표시 | 안 올린 상태가 모두에게 보이면 상호 압박이 걸린다 |
| 팀원별 저장소를 내비에 고정 노출 | "내 저장소가 있다"는 감각이 축적 동기를 만든다 |
| 정리본·지식 분류는 전부 자동 생성 | 사람이 정리 당번을 맡으면 2주 안에 무너진다 |

## 3. 사용자

**4명 고정.** 회원가입 없음. 팀 개념 없음(DB에 팀 테이블이 없다).

계정은 관리자가 Supabase 대시보드에서 직접 만든다. 이 선택 하나로 초대 흐름·권한 등급·가입 검증이 전부 사라졌다.

읽기는 4명 전원, 쓰기·수정·삭제는 본인 것만.

## 4. 핵심 구조 4가지

1. **팀원별 스터디 저장소 4개** — 각자의 노트가 자기 저장소에 쌓인다
2. **업로드** — 마크다운 본문. 웹에서 직접 쓰거나, 이미 만들어둔 `.md` 파일을 불러온다
3. **날짜별 정리본** — 그날 올라온 노트를 AI가 읽고 하나의 문서로 묶는다
4. **마인드맵 지식 그래프** — 같은 AI 호출 한 번으로 노트를 주제(topic)로 분류하고 주제 간 관계를 누적한다. 정리본이 "오늘 하루"를 묶는다면, 마인드맵은 "날짜를 넘나드는 누적 지식"을 묶는다

## 5. 성공 기준

- 노트를 올리는 데 필요한 입력이 제목·날짜·본문뿐이다
- 아침에 접속하면 어제 정리본이 준비돼 있다
- **정리본이 없는 연결고리를 지어내지 않는다** — 마인드맵도 같은 원칙을 따른다
- 운영 비용 0원

세 번째가 가장 중요하다. 각자 자유 주제로 공부하니 서로 무관한 날이 자주 생기는데, 이때 AI에게 연결을 찾게 하면 "두 분 다 본질적으로 구조적 사고를 다루셨습니다" 같은 문장이 나온다. 이런 게 한 번 나오기 시작하면 팀은 정리본을 안 읽게 된다. **정리본이 지루한 것보다 신뢰를 잃는 쪽이 훨씬 치명적이다.**

그래서 연결 판정은 프롬프트에 맡기지 않고 코드가 검증한다 — 연결에 언급된 사람이 그날 실제로 노트를 올렸는지 확인하고, 유효한 게 하나도 없으면 "겹치는 지점" 섹션을 마크다운에서 통째로 지운다. 연결이 없는 날은 그냥 아무 말도 안 한다.

마인드맵의 주제 분류도 같은 원칙이다 — AI가 근거 문장(evidence quote)을 원문에서 그대로 인용하지 못하면 그 분류 자체를 버린다. 판정 절차는 [시스템 설계도 §4](2026-08-06-study-hub-architecture.md)에 도식으로 있다.

## 6. 범위 밖

의도적으로 뺀 것들이다. 필요해지면 그때 별도 설계로 다룬다.

| 제외 항목 | 근거 |
|---|---|
| 첨부파일 내용 파싱·PDF 추출·OCR | 비용과 복잡도가 폭발하는 지점 |
| 일반 첨부(PDF·이미지) 업로드 | 2단계 재검토에서 제외. `attachments` 테이블·RLS는 이미 있으나 미사용. 계획서는 [별도 보관](2026-08-05-study-hub-attachments-plan.md) |
| 마인드맵 주제의 사람 검수(승인/반려) UI | AI-only 결정론적 검증(근거 원문 대조)으로 대체. 사람 검수는 4명 규모에 과잉이다 |
| 팀 여러 개, 초대 흐름, 권한 등급 | 4명 고정이라 불필요 |
| 댓글, 좋아요, 알림, 이메일 | 4명은 카톡으로 말한다 |
| 모바일 앱 | 반응형 웹으로 대응 |

## 7. 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| **1단계** | 로그인, 노트 CRUD, 팀원별 저장소, 홈, RLS·권한 테스트 | **완료** |
| **2단계** | 마크다운 파일 불러오기, 본문 마크다운 렌더링 | **완료** |
| **3단계** | AI 정리본, 크론, `.md` 다운로드, 아카이브 화면 | **완료** |
| **4단계** | 마인드맵 지식 그래프 — 주제 분류, 주제 관계, `/mindmap` 화면 | **완료** (다듬는 중) |

**계획한 범위는 전부 구현됐다.** 남은 것은 대부분 코드가 아니라 사람이 해야 하는 설정이다.

| 확인할 것 | 비고 |
|---|---|
| `service_role` 키 재발급 | 채팅에 노출된 적이 있다. **3·4단계 파이프라인이 실제로 사용한다** |
| `GEMINI_API_KEY` 발급·등록 | aistudio.google.com, 무료 |
| `CRON_SECRET` 설정 | Vercel 환경변수. 크론은 `Authorization: Bearer $CRON_SECRET` 으로 호출한다 |
| 배포 후 크론 검증 | Vercel 크론은 배포 환경에서만 동작한다. 그 전에는 "다시 생성" 버튼으로 확인 |

## 8. 대략적인 구조 — 무엇이 어디서 도는가

깊은 설계는 [시스템 설계도](2026-08-06-study-hub-architecture.md)에 있다. 여기서는 큰 덩어리만 잡는다.

```
[브라우저]
   │  로그인 세션(쿠키) + anon 키로만 DB 접근
   ▼
[Vercel — Next.js App Router]
   ├─ 서버 컴포넌트(page.tsx)  ─── 화면 렌더링, RLS 뒤에서 조회
   ├─ 서버 액션                ─── 노트 CRUD
   ├─ middleware.ts            ─── 세션 갱신 · 비로그인 차단 (/api 제외)
   └─ /api 라우트 3개           ─── 자체 인증 (크론·정리본 생성·다운로드)
          │
          ├─ digest-pipeline  ─── service role로 노트 조회, 상태 기록
          │     ├─ digest-generation / digest   ─── 정리본 조립 (순수 함수 + AI 주입)
          │     └─ knowledge-generation          ─── 마인드맵 분류 파싱·검증
          └─ ai/gemini.ts     ─── 유일한 네트워크 호출 지점
   ▼
[Supabase] Auth · Postgres(RLS) · Storage(테이블만, 미사용)
   ▼
[Google AI Studio] Gemini — 정리본 + 마인드맵을 한 호출로 처리
```

**설계 원칙 두 가지**가 이 구조 전체를 관통한다.

1. **권한은 화면이 아니라 Postgres RLS가 강제한다.** 앱 코드는 로그인 세션의 anon 키로만 DB에 접근한다.
2. **service role(= RLS 우회)을 쓰는 경로는 자기 손으로 직접 인증한다.** 크론은 `CRON_SECRET`, 수동 생성 API는 세션의 `profiles` 등록 여부를 직접 확인한다 — RLS에 기댈 수 없기 때문이다.

## 9. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 15 (App Router) + TypeScript | React 19 |
| 스타일 | Tailwind v4 | |
| DB · 인증 · 파일 | Supabase | 무료 티어 |
| 배포 | Vercel Hobby | 크론 1일 1회 제공 |
| 마크다운 렌더 | `react-markdown` + `remark-gfm` | 원시 HTML 렌더링 안 함 (기본값 유지) |
| AI | Google AI Studio (Gemini) 무료 티어 | `@google/genai` · `lib/ai/` 한 곳에만 존재. `responseSchema`로 JSON 강제 |
| 테스트 | Vitest | 단위 + RLS(권한) |

**AI 제공자 선정 근거**: 노트가 전부 한국어이며, 무료로 열려 있는 오픈모델 대비 한국어 요약 품질이 안정적이다. 키 발급에 결제 수단이 필요 없다. 예상 사용량은 하루 1~5회로 어떤 무료 한도에도 근접하지 않는다.

## 10. 리스크

| 항목 | 내용 | 대응 |
|---|---|---|
| 무료 Gemini API 데이터 취급 | 전송된 노트 본문이 모델 개선에 쓰일 수 있다 | 팀에 사전 공유. 기밀 정보를 올리지 않는다 |
| Supabase 무료 프로젝트 일시정지 | 약 7일 이상 미사용 시 자동 정지 | 매일 사용하므로 실질적 영향 없음 |
| Vercel Hobby 크론 | 1일 1회만 가능 | 요구사항이 1일 1회라 부합. 더 잦은 실행이 필요한 기능을 설계하지 않는다 |
| 정리본 품질 | AI 요약이 기대에 못 미칠 수 있다 | 원본 노트가 항상 보존되고 링크된다. 정리본은 보조 수단이다 |
| 마인드맵 오분류 | AI가 주제를 잘못 붙일 수 있다 | 근거 문장을 원문에서 대조 검증. 통과 못 하면 그 매핑을 버린다 |
